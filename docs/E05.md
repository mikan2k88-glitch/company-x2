# E05 — 依頼受付と作業計画

依頼例を選び、CSVを入力して「作業計画を作成」を押すと、処理範囲・入力行数・納品行数・形式を表示します。条件に同意して「計画どおりに自動処理」を押すと、永続キューで制作・検品を実行し、成果物をダウンロードできます。

## 起動・デプロイ

E04までの環境変数とSQLをそのまま使います。E05専用のSQL・新しいキー・有料APIは不要です。E04の004_data_services.sqlが未適用の場合は先に適用してください。重複除去は既存の002のまま使えます。

RenderのStart Commandは `python -m company_x2.server`。mainの最新コミットをデプロイし、ページを再読み込みしてください。`/api/health` のendpointがE05になり、依頼文の欄が表示されれば更新されています。healthだけでは004適用の確認にはなりません。`/api/services` で追加サービスのavailableがtrueか確認できます。

## 対応範囲

依頼文は定型文を全文照合します。画面の4つの依頼例のほか、対応する丁寧形・英語の定型文を受け付けます。自由な自然言語理解をするAIは未接続です。複数の処理、独自の除外条件、メール送信などは受付せず、勝手に処理範囲を広げません。

計画作成は制作と検品を事前実行しますが、注文・成果物を保存しません。計画にはCSVのセル値を含めず、入力ハッシュと処理条件・行数だけを返します。実行時は入力から計画を再計算し、ハッシュが一致した場合だけ注文を保存します。画面で入力を変えると計画への同意をリセットします。

注文にはサービス・入力・成果物・進行イベントを保存します。依頼文と計画全文の履歴保存は未実装です。再起動後の注文処理と同じrequest_keyでの再送は既存の仕組みを使います。実行APIの応答が届かない場合は、入力を変えず同じ実行ボタンで再試行してください。ページ再読み込み前の未確定リクエストはブラウザーに永続保存していません。

## API

- `GET /api/plans`: 対応する依頼例
- `POST /api/plans`: JSONのrequestとcsvから計画を作成。保存・受付はしません。
- `POST /api/plans/run`: 同じrequestとcsv、plan_sha256、request_key、terms_accepted=trueを指定。X-Order-Tokenで所有者を指定し、202で注文IDを返します。
- 注文の進行確認と納品は既存の `/api/orders/{id}` と `/api/orders/{id}/download`。

公開環境ではBasic認証も必要です。注文所有者トークンは別途必要です。計画ハッシュは入力変更検出用で、認証・契約の証明ではありません。

## 完了条件と残り

対応依頼→入力検査→計画→注文保存→制作→検品→ダウンロードを無料検証環境で実行できます。募集候補の自動探索は独立した機能で、候補から依頼の成立や顧客データの取得は行いません。AI判断、営業・応募、顧客との合意、外部への納品、決済・入金照合は今後の開発範囲です。実売上は0円です。
