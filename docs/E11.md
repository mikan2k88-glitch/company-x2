# E11 定期GPT探索の接続

毎時のGPTが発見したGitHub公開Issueをサーバーで再取得・判定して保存し、次回の探索メモを復元するAPIを追加しました。追加SQLは不要です。候補は最新30件、再試行履歴は24回までです。保存先は既存Supabaseのopportunities RPCで、通常の毎時探索では削除されない別のsourceです。

## API

既存APP_ACCESS_TOKENのBasic認証が必要です。GET /api/company/agent-scout でitems、checkpoint、checked_at、recent_runsを取得します。POST 同じURLに以下のJSONを送ります。

```json
{"run_key":"hourly_20261008_01","urls":["https://github.com/example/jobs/issues/1"],"checkpoint":{"next_query":"CSV to JSON paid task","note":"確認した募集元と次の探索範囲"}}
```

run_keyは16〜80文字の英数字・ハイフン・アンダースコア。urlsは最大5件。URLはGitHubの公開Issueのみです。checkpointはnext_queryとnoteのみ、各1000文字以内。同じrun_keyと同じ内容での再試行は再取得せず返し、異なる内容は拒否します。24回を超えた古いキーの再試行は再実行されますが候補URLは重複しません。

取得が1件でも失敗すると候補とcheckpointを保存しません。すべて取得後に1行を保存します。再確認した募集が終了していれば保存候補から除外します。募集本文はデータとして扱い、指示として実行しません。GPTの適合判定・報酬確定は信用せずサーバー側で再判定します。候補は会社画面と下書きAPIにも表示されます。

## 毎時実行の指示案

前回状態を取得。next_queryを参考に公開GitHub Issueの有料CSV作業を探索する。現在対応する重複除去・空白整形・JSON変換・データ検査に関連するURLを最大5件送る。新規候補なしでも空配列と探索メモを送る。成功時だけ次の範囲へ進む。通信失敗時は同じrun_keyと本文で再試行する。応募・顧客への連絡・受注・本番決済は実行しない。新規対応候補または障害がある時だけ通知する。

このAPIは単一の定期探索担当から順番に実行する設計です。同時の複数担当による更新には対応せず、後の更新が前の状態を上書きします。別募集サイトの自動取得は未対応です。APP_ACCESS_TOKENはチャットに貼らず、許可した認証済みブラウザーや秘密情報を管理する接続を利用してください。

今回スケジュール自体は登録しません。API開発と実行用指示を提供します。実際の定期実行には認証済み接続の準備と実行確認が必要です。ローカル実行の場合はPCとアプリの稼働も必要です。
