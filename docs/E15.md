# E15 — 営業判定と顧客用の検証受付リンク

会社画面 `/company` に営業判定、条件確認の案内文、期限付き受付リンクを追加しました。

## 営業判定
保存済み14件のうち、従来の対応候補2件を原文で確認しました。OmiのSerbian quickstartは翻訳の報酬提案で、報酬を支払う募集ではありません。Familiariseは事業計画です。CSVの記載はサンプルや事業説明でした。またCSV deduplication CLIの2 USDCは売り手の出品でした。

- https://github.com/BasedHardware/omi/issues/13444
- https://github.com/Practitionist/familiarise_web/issues/1748
- https://github.com/mundodr/ten-dollar-wallet-test/issues/2

CSV加工の直接依頼・対応範囲・新しさを満たすものだけを範囲候補とします。案内文は発注意思、報酬・支払い条件、納期、AI利用・応募許可、入力の確認を求める下書きです。金額やCSVという単語だけを根拠に応募・受注しません。現状で有償受注先を確保できたとは判断しません。

## 顧客用受付リンク
会社画面でサービスを選び「受付リンクを作成」を押すと、7日間有効な検証用リンクを作成します。実際の送信は行いません。管理パスワードを共有する必要はありません。

リンクを持つ利用者は無料検証またはStripeテスト100円の計画作成・受付・テスト決済・制作・成果物取得・受領記録を利用できます。会社運用、営業情報、AI、別リンク発行にはアクセスできません。注文は別の所有者トークンで隔離します。

署名付き受付アクセスはURLのフラグメントから同じタブのsessionStorageへ保存し、URLから除去します。注文トークンと受付アクセスを失うと、そのタブの進捗を再表示できません。リンクを知る人は有効期間内に検証受付を利用できます。個別リンクの失効は未実装で、APP_ACCESS_TOKENの変更は全リンクを失効させます。

受付HTMLは公開の静的シェルです。APIは管理認証または有効な受付アクセスが必要です。本番決済・本番価格は未対応です。Stripeへはテストセッションだけを作成します。

追加SQLと環境変数は不要。既存のAPP_ACCESS_TOKENをサーバー内の署名鍵として利用し、鍵はリンクに含めません。

## 検証
顧客用アクセスでテスト決済の署名照合→制作・検品→ダウンロード→ハッシュ照合→受領記録を確認。管理APIへのアクセス拒否、期限切れ・改ざん・鍵変更・別注文へのアクセス拒否、本番決済の拒否をテストします。
