# E18 — 公開無料検証

/services → /intake の「無料検証を開始」から招待なしで検証できます。日英表示、計画確認・同意・制作・検品・ダウンロードのハッシュ照合・受領記録を利用します。公開用アクセスは1時間、ブラウザーの所有者トークンに署名で結び付けます。期限切れは同じタブで開始し直せます。別の注文・管理API・AI・Stripe Checkout・招待リンク発行への権限はありません。

公開入力はUTF-8 CSV 50,000バイト・1,000行、無料モードのみ。1日全体10件、所有者トークンあたり2件、開始30回、計画60回。所有者は匿名トークンであり人物認証ではありません。全体上限はトークン変更でも維持。UTC日、日本時間9時に更新。公開APIにはプロセス内120リクエスト/分の共有制限があり、超過時429を返します。

利用予約は既存Supabaseのopportunity RPCへ先に保存します。失敗・曖昧な保存では受付を進めず、再試行は同じキー・内容・所有者で行います。日付をまたぐ同一依頼も既存予約へ戻ります。保存失敗で予約だけ消費する場合があります。既存DBキューの100件上限も維持。追加SQLや設定は不要です。

ロックは現在の単一Pythonプロセス内の同時受付を直列化します。再起動後の件数はDBから復元しますが、複数プロセス・レプリカ間の原子的な割当ではありません。デプロイ切替時のプロセス重複を含め厳密な分散上限が必要なら専用の原子的RPCへの移行が必要です。複数レプリカへ拡張しないでください。既存RPCが返す最新100レコードに当日の利用記録が見つからず100件埋まっている場合は、上限をリセットせず停止します。

会社画面に保存済み最大30日の紹介ページ表示（タブからの申告・重複あり）、開始、受付、受領済み納品を表示。表示イベントは日・タブのランダムキーで重複を除き、最大200件/日。原文のCSV・所有者トークン・IPを集計に保存しません。CSVと成果物は既存の注文ストレージへ保存します。自動削除・人物認証・本番課金は未実装です。

検証: 招待・管理認証なしの公開開始→計画→受付→制作→ハッシュ一致→受領記録、管理/AI/決済への拒否、所有者違い・期限・容量・行数・全体/所有者上限、同時16件から10件のみ受理、DB再接続後上限、日をまたぐ再試行、DB失敗時停止。既存の招待受付・Stripeテスト・PostgreSQL CIも確認。
