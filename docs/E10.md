# E10: 探索から依頼受付へ

会社運用画面 `/company` で、保存済みの最新最大30候補を対応候補・更新日不明・古い候補・対象外・重複候補に整理します。90日を超えて更新がない募集は古い候補に分類します。更新日は募集継続の証明ではありません。同一URLまたは正規化した長い募集名による重複候補は画面で分け、削除しません。

対応候補の「対応範囲と見積もり案を確認」で、対応サービス・必要なCSV・無料検証0円・Stripeテスト100円を表示します。実データがないため本番価格・行数・成果物は未確定です。候補から会社画面のサービスを選択できます。外部への応募送信や受注は行いません。

## 専用受付

`/intake` でサービス選択 → UTF-8 CSVファイルまたは本文 → 作業計画 → 条件への同意 → 受付 → 必要ならStripeテスト決済 → 制作・検品 → ダウンロード・受領記録を行います。1MB・10,000行まで。CSV本文は計画作成時にサーバーへ送信され、AIには送りません。

このページにもAPP_ACCESS_TOKENによる認証が必要です。パスワードを共有した限定検証用で、一般顧客のアカウント機能ではありません。同じタブのsessionStorageに注文トークンを保存して再開します。Stripeからも受付画面へ戻ります。ダウンロードはSHA-256一致を確認して受領を記録します。

## 設定と検証

既存のE09 SQL（schema_version=9）を利用するため追加SQL・環境変数は不要です。公開ヘルスのendpointはE10になります。Stripeはテストのみで、実際の支払い・実売上は発生しません。新しい探索サイトや自動応募は追加していません。

分類・重複・拒否候補の維持・保存候補のみの下書き・認証・限定設定の取得・制作への接続・決済戻り先の許可リストをテストします。既存の決済・納品・PostgreSQLテストもCIで実行します。
