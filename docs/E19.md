# E19 — Stripe本番キー対応（有効化は別設定）

本番用 `STRIPE_LIVE_SECRET_KEY=sk_live_...` と `STRIPE_LIVE_WEBHOOK_SECRET=whsec_...` をテスト用と分離。既存のSTRIPE_SECRET_KEYがsk_liveの場合も本番へ割り当てますが、別変数を推奨します。テストキー・署名キーは従来の変数のまま保持。キーはサーバーにのみ保存し、HTMLやAPI応答には出しません。

本番Webhook URL: https://company-x2.onrender.com/api/payments/live-webhook
イベント: checkout.session.completed / checkout.session.async_payment_succeeded
テストWebhook URLは /api/payments/webhook のまま。署名・5分の時刻許容・event/sessionのlivemode一致・cs_liveとcs_test・支払済み・完了状態・金額・JPY・注文ID・既存セッションとの一致を確認。重複通知は同じ証拠なら再処理しません。新規課金を停止しても、既存注文の本番通知と再照合は受け付けます。

有効化には、019_live_payments.sqlを既存E09のDBへ適用し、APP_PUBLIC_URL、本番キー、本番Webhook署名キー、LIVE_PRICE_JPY（整数50〜10000円）、同じオリジンの公開済み販売条件SALES_TERMS_URL、LIVE_SALES_TERMS_CONFIRMED=true、LIVE_PAYMENTS_ENABLED=trueが必要です。料金に既定値はありません。条件URLと販売者・返金条件の内容を確認してからフラグを設定してください。フラグは運営者の確認であり、内容をアプリが法的に審査するものではありません。

会社画面で本番の準備不足理由を確認できます。準備完了後、本番決済用の顧客リンクを発行します。既存テスト招待・公開無料アクセスでは本番注文を作れません。本番受付には実際の金額・販売条件リンク・実課金の表示と同意を追加。価格・条件URLは計画ハッシュに含め、変更時は新しい計画が必要です。管理会社画面の従来作業フォームは検証専用です。

019は同じRPCにlive_pingを追加し、テスト履歴を維持します。pingのschema_versionは9のまま、本番capabilityはlive_schema_version19です。未適用でも無料・テスト運用と起動は可能で、本番は停止します。過去の009を019の後に再適用しないでください。

本番入金合計とテスト入金を分離。受領済み本番入金合計（従来フィールドreal_revenue_jpy）は、会計上の利益や手数料・返金控除後金額を示しません。本番入金済み処理失敗を管理画面に表示します。制作の既存再試行は維持。自動返金・返金通知反映・税務計算は未実装で、失敗時は運営者による個別対応が必要です。広く販売する前にこれらの運用を整えてください。

検証は模擬Stripe証拠で実施し、実カード・実課金は行いません。キーが実際に有効かは設定の形式判定とは別です。SQLのPostgreSQL CIは入金照合、再通知、制作、受領、モード混同拒否を実DBで検証。
