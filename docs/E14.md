# E14 — クラウド探索の障害診断と再試行

Renderの無料Webサービスと、非公開Sites接続を利用するChatGPTクラウドタスクを組み合わせています。デスクトップの旧タスクは停止。有料Render Cronは作成していません。

接続窓口: https://company-x2-cloud-bridge.mikan2k.chatgpt.site
所有者限定。各タスクはSitesのget_siteからその回のサービスアクセスを取得します。秘密キーやPCのファイルをタスクの指示に含めません。

GitHubの取得失敗をDB障害と区別し、検索／Issue照合、HTTP状態、取得制限、応答不完全などを固定コードで返します。応答本文・認証・URLはログに残しません。GitHubのRetry-After／取得制限の解除時刻に応じて待ち、候補と探索範囲を保ったまま再試行します。成功時に障害状態を解消します。

`attempt_`の失敗記録は最終成功に数えません。会社画面に最終成功と取得待ちの原因・再試行可能時刻を表示します。追加SQLは不要です。

任意の`GITHUB_SCOUT_TOKEN`をRenderに設定すると公開GitHub APIの専用認証を利用できます。公開情報の取得だけに必要な最小権限を使ってください。未設定でも取得できます。リダイレクトには認証を転送しません。

毎時タスクは保存済みです。保存履歴に複数回の成功と失敗記録があり、クラウドからの更新を確認しました。検索結果は有償案件の成立や応募許可を保証しません。応募・本番決済は行いません。

検証: ソース障害の診断、待機中の通信抑止、チェックポイントと候補の保持、成功後の回復、失敗記録と最終成功の分離、HTTP診断と既存注文・決済の回帰テスト。
